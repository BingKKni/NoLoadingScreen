# 切服修复测试说明

> NeoForge 1.21.10/.11 的独立构建、CLIENT 转换/行为检查、可选模组矩阵及 GPU 冒烟命令见 [NEOFORGE.md](NEOFORGE.md)。下文保留原 Fabric 26.2 证据与实机清单。

适用版本：Minecraft 26.2、Fabric Loader 0.19.3 或更高、Java 25。当前版本：1.1.0。

## 1.1.0：多平台实机修复与 GPU 回归

NeoForge 1.21.10/1.21.11/26.1/26.2、Forge 26.2 与 Fabric 26.1 上实测发现的问题及处理结果：

| 反馈 | 根因 | 处理 |
|---|---|---|
| 1.21.x 单人保存退出时视角抽搐，1.21.11 无法移动 | 保存等待由菜单点击触发，此时已经在一个客户端任务内部；1.21 的保存帧路径在呈现时会再次轮询 GLFW，而原版 `Minecraft.execute` 在任务嵌套时把回调排队，只有等待结束后才执行，导致输入部分丢失或整批延后 | `LoadingWaitLoop` 在整个本地帧（轮询、tick、绘制）期间内联分发同线程输入，不再只在自己的轮询内内联。不改动任务队列，等待期间仍不抽干客户端任务/数据包 |
| 1.21.x KickWarn 占位中疾跑不改变 FOV | 1.21 的 FOV 插值位于 `GameRenderer.tickFov`（私有），26.x 在 `Camera.tick` 内；1.21 场景 tick 只推进相机 | 1.21 平台 `SceneRenderer.tickCamera` 通过 accessor 先调用 `tickFov` 再 tick 相机 |
| 1.21.x KickWarn 物品栏悬停无物品提示 | 旧版容器界面把 tooltip 提交留给具体子类 | 1.21 的 `InventoryScreenAdapter.render` 在 `super.render` 后调用 `renderTooltip` |
| 中键按住转向再松开会拾取别的方块 | **未复现**。原版 `KeyMapping.click` 只在按下时触发，`pickBlock` 读取按下那一刻的 `hitResult`；7 个平台的真实 GLFW 按下/按住/转向/松开回归均保留第一次瞄准的方块 | 保留断言；需补充复现步骤、是否开着菜单及 `latest.log` |
| NeoForge 26.2 冷启动后首次进图掉帧 | 26.x NeoForge/Forge/Fabric 26.1 层此前用 `supported()=false` 覆盖 Sodium 白名单，所以类型预热、地形管线预编译、单工作线程、首次重建合并全部未启用 | 删除 NeoForge 26.x 的覆盖文件，共享的精确版本白名单 `0.9.2+mc26.2` 直接生效。新增 NeoForge 26.x `verifyCompatibility`，用真实 Sodium NeoForge JAR 验证 7 个私有钩子和实际 collector 行为 |
| NeoForge 26.2 快捷栏物品放入背包时没有换手动画 | `Player.tick` 会比较 `lastItemInMainHand` 并在物品不同时重置 `itemSwapTicker`；占位视觉 tick 只推进 ticker 不比较 | `PlaceholderVisuals.trackMainHandItem` 复刻原版比较：`matches` 相同则跳过，`isSameItem` 不同则 ticker 归零，保存副本 |
| Forge 26.2 无法加载（ResourcePackInfo / pack.mcmeta 警告） | Forge 读取每个 Mod JAR 的 `pack.mcmeta`，不会补全 | `gradle/forge-pack-resources.gradle` 从游戏 JAR 的 `version.json` 读取 `pack_version` 生成 `pack.mcmeta`；`verifyModernArtifact` 与 Forge 的 `verifyClient` 校验该文件可被 `Pack.readPackMetadata` 解析 |

以上改动都在共享源码或平台适配层内，没有按版本号分支的运行时判断。Sodium NeoForge 发布包把真正的类放在 `META-INF/jarjar/` 内嵌 JAR 中，FML 用 `jarinjar` 定位器加载，因此白名单按 `sodium` 的 Mod 版本判断，不看外层 JAR 内容。

新增 `verifyRepairGpu`（不属于 `check`/CI）：在目标自己的 `build/repair-gpu` 中启动真实 GPU 客户端，依次执行合成占位、提升为实时会话后运行真实的 `Minecraft.disconnect` 保存等待（用 GLFW 回调交换注入 W 键和逐帧鼠标移动，断言视角转动量、玩家位移、相机无回退/无跳变）、多人踢出的 KickWarn、中键按下/按住/转向/松开、换手动画、离线疾跑 FOV、物品栏帧，最后清理并退出。集成服务端探针只覆盖 `isShutdown`/`halt`，不构造服务端、不动存档。

```bash
# 26.x 目标（JAVA_HOME 指向 JDK 25）；资源索引：26.1 用 30，26.2 用 32
./gradlew -p platforms/neoforge-26.2 verifyRepairGpu -PassetsDir="/path/to/assets" -PassetIndex=32
./gradlew -p platforms/neoforge-26.2 verifyRepairGpu -PsmokeModJars="/path/to/sodium-neoforge-0.9.2+mc26.2.jar" -PassetsDir="/path/to/assets" -PassetIndex=32
./gradlew -p platforms/neoforge-26.2 verifyCompatibility -PcompatibilityJars="/path/to/sodium-neoforge-0.9.2+mc26.2.jar"
# 1.21 目标（JAVA_HOME 指向 JDK 21）；资源索引：1.21.10 用 27，1.21.11 用 29
./gradlew -p platforms/neoforge-1.21.11 verifyRepairGpu -PassetsDir="/path/to/assets" -PassetIndex=29
```

`assetsDir` 可以直接指向 ModDevGradle 的 `downloadAssets` 缓存（默认 `~/.gradle/caches/neoformruntime/assets`）。实测结果：root Fabric 26.2、Fabric 26.1、NeoForge 26.1/26.2、Forge 26.2、NeoForge 1.21.10/1.21.11 七个目标无 Sodium 通过；NeoForge 26.2 与 Fabric 26.2 装载 Sodium `0.9.2+mc26.2` 通过（日志出现 `Prepared Sodium terrain pipelines`）。1.21.11 的保存等待做过红绿对照：撤销修复后视角转动为 0、位移为 0，恢复修复后与注入量一致。测试窗口失去宿主焦点时原版会丢弃鼠标增量，回归会重新置焦并把次数记入日志，不当作 Mod 缺陷。

这些是隔离的短时 GPU 回归，不是整合包、真实存档或服务器验收；1.21.10 的“视角抽搐”在回归中未观测到相机回退，若仍出现请按下方清单保留日志。当前测试所用的 Sodium `0.9.2-alpha.4+mc26.2` 不在白名单内，私有优化不会启用，需换用正式版 `0.9.2+mc26.2`。

## 优化 Mod 兼容矩阵与离线快捷栏文字修复

离线占位世界渲染时会临时绑定玩家，但普通 `Gui.tick` 之前没有为 `Hud.tick` 绑定，因此原版 `toolHighlightTimer` 看不到玩家并停止递减，快捷栏物品名会永久停留。现在只包装 `Gui.tick → Hud.tick(boolean)` 这一处现有调用：保持原版调用次数、暂停语义、物品变化判断和通知时长，同时不让占位玩家进入死亡/睡眠/界面生命周期分支。无窗口回归覆盖切换物品、逐 tick 递减、暂停不递减、切到空格立即清除及绑定还原。

Sodium 私有钩子现在只对 Minecraft 26.2 当前最新正式版 `0.9.2+mc26.2` 精确支持；未知或预发布版本不会尝试套用私有布局。新增可选组合检查：

```bash
./gradlew verifyOptimizationCompatibility -PoptimizationModJars="/path/to/mods-directory"
# 也可用逗号或分号列出多个 JAR/目录
```

该任务只加载调用者提供的未修改 JAR，强制转换共享的 Minecraft/Gui/Hud/渲染/连接目标，并检查 NoLoadingScreen 钩子仍在；不会下载或打包第三方 Mod，也不打开窗口。已通过的基础矩阵包含 Sodium 0.9.2、Iris 1.11.4、ImmediatelyFast 1.16.4、Lithium 0.25.3、FerriteCore 9.0.0、EntityCulling 1.10.5、MoreCulling 1.8.1、Dynamic FPS 3.11.9、Sodium Extra 0.9.3、RRLS 5.2.8、Fabric API 0.158.0、Cloth Config 26.2.155 和 ViaFabricPlus 5.0.1；扩展矩阵另包含 Bobby 5.2.15、Distant Horizons 3.2.0-b、FastQuit 3.1.5 和 Reese's Sodium Options 2.2.3。这里证明的是 NoLoadingScreen 目标转换在这些 Mod 加载后没有丢失，不是第三方 Mod 自身功能、GPU/FPS 或实际玩法结论。

另用实际 JAR 通过：

```bash
./gradlew verifyLoadingCompatibility -PsodiumJar="/path/to/sodium-0.9.2.jar" -PfabricApiJar="/path/to/fabric-api.jar" -PviaFabricPlusJar="/path/to/ViaFabricPlus-5.0.1.jar"
```

这证明对应版本能共同解析依赖并完成 Mixin 转换及已有调度断言，不代表 Iris 着色器、EntityCulling 后台线程、完整整合包 FPS 或真实跨协议服务器已经实机验收。渲染器/着色器 Mod 仍须按下方实机清单复测。

## 首次进图冷启动

此处不改皮肤逻辑。新增类型预热、Sodium 地形管线预编译、首次渲染器重复重建合并、合成虚空单工作线程，并补齐 Fabric 配置阶段槽位保护。证据与限制见 [增量说明](LOADING_IMPROVEMENTS.zh-CN.md)。启动收尾时间会增加，不宣称所有加载逻辑异步或完全消除首次卡顿。

`check` 增加类型解析不执行初始化器/构造器的检查；`verifyLoadingCompatibility` 增加实际管线对象复用、首次重建及资源/视距失效、工作线程隔离、配置 addon 保护。只对已验证的 Sodium 版本启用私有钩子。

可选真实 GPU 冒烟测试，不属于常规构建/CI：

```bash
./gradlew verifyColdStartGpu -PsodiumJar="/path/to/sodium.jar" -PfabricApiJar="/path/to/fabric-api.jar" -PassetsDir="/path/to/assets" -PassetIndex=32
```

它只在 `build/cold-gpu-run` 运行，使用测试身份和指定的只读资源目录，不打开存档、不建立游戏服务器连接；原版账户/Realms 后台请求可能产生测试身份鉴权错误。显示占位场景 3 秒后检查绑定及交换链并退出，任务超时两分钟，缺少成功标记即失败。测试 Mixin 只在测试资源中，不进可分发 JAR。加 `-PcoldProfile` 可在测试目录生成 `cold-start.jfr`。

已在 RX 580/OpenGL 上通过。JFR 指向首次 JAR 读取、类型加载及 Mixin 转换；加入类型预热后，两次独立运行的首次占位安装约 195、197 ms，开发中间态约 311 至 338 ms。此数据不是完整整合包前后版本基准，也不说明真实区块加载已无卡顿。预热后仍约 200 ms 的初始开销和完整整合包/实服帧时间仍须复测。

检查启动日志的 `Prepared first-join class definitions`、`Prepared Sodium terrain pipelines`；若还有长卡顿，保留新的 `packet <包类>`、`Sodium renderer initialization/teardown` 和 `render frame` 慢日志。嵌套计时不可相加。资源包重载后允许重新编译，真实/接管世界的线程数及视距不得被缩减。

## 皮肤交接与加载响应

实现和证据见 [加载改进说明](LOADING_IMPROVEMENTS.zh-CN.md)。版本保持 1.0.5，不改语言文件。已通过常规无窗口检查，以及实际安装的 Sodium 0.9.2 / Fabric API 0.158.0 / ViaFabricPlus 5.0.1 原始 JAR 兼容检查；未宣称完成 FPS 或真实服务器验收。

新增 `LoadingWorkVerification` 覆盖真实收包/任务队列的软预算、FIFO、至少一个任务前进、原异常路径、非客户端队列隔离、同步完成等待、保护期退出和原版异步建模路由。实体皮肤回归增加占位到真实玩家、无 PlayerInfo、延迟纹理、服务端换肤和完成空结果等情况；另模拟缓存过期返回不同 Future 与账户皮肤迟到，保证就绪判断仍属于原版正在使用的那次查询。

可选兼容检查（路径指向自己的未修改 JAR）：

```bash
./gradlew verifyLoadingCompatibility -PsodiumJar="/path/to/sodium.jar" -PfabricApiJar="/path/to/fabric-api.jar" -PviaFabricPlusJar="/path/to/ViaFabricPlus.jar"
```

实机对照必须分别重启客户端，否则冷启动和热缓存混在一起不能归因：

1. 保持同一存档、同一资源包和渲染距离，比较仅本 Mod、仅 Sodium、两者同时使用及两者都不使用。整合包测试另记其他 Mod；不要为对照删除存档或皮肤缓存。
2. 每组记录首次进入后至少 15 秒的帧时间，再记录同一存档重进和另一存档首次进入。日志里的 `Join finished` 只表示提前就绪，不是所有网格完成，更不是帧率结果。
3. 本地/授权多人服批量发区块时，观察等待世界、接收区块及进图后能否持续转头、F5；允许地形稍后呈现，不应要求同一帧建完。检查位置/能力/背包以服务端为准，退出、重连和切服无丢包/超时异常。
4. 预热皮肤后分别看占位、真实世界首帧、E 和 F5；服务器自定义换肤及明确默认皮肤完成后必须接管，其他玩家不得被覆盖。皮肤下载本身未完成时仍可显示默认皮肤。
5. 用 ViaFabricPlus 4.6.2 复测切服，日志不应再出现 `enableAutoRead` 访问空 channel。Fabric play addon 已占用时允许保留加载界面，但不得破坏真实连接。
6. 记录 `[loading-work]` 的具体阶段。`client packet drain` / `client tasks` / `client tick` / `render frame` / `login world assembly` 可区分慢调用区域，但单个包/任务不可抢占，GPU/驱动、GC/JIT 仍需 JFR 或帧时间分析。日志会限量，不把未打印视为绝对无卡顿。

分帧接收会推迟部分包处理和对应回复，不改变队列顺序；8 ms 收包/4 ms 普通任务是软预算。加载保护在提前就绪后持续 5 秒，随后恢复正常策略。Sodium 的强制完整帧模式继续等待全部结果，包括加载时暂缓等待的旧批次；兼容钩子仅对当前已验证的正式版 `0.9.2+mc26.2` 启用，其他版本保留其原生调度，需重新验证。单次渲染器销毁、资源/着色器提交等同步开销仍可能卡帧。

## ViaFabricPlus 启动冲突修复

- 已用 ViaFabricPlus 4.6.1 原始 JAR 复现：两边都以 `@Redirect` 修改 `Minecraft.execute(Runnable)`，导致 ViaFabricPlus 的 `storeEvent` 找不到注入点，启动时 `MouseHandler` 转换失败。键盘也存在同类重叠。
- 鼠标和键盘现改用可串联的 `@WrapOperation`。只有同步等待中本模组主动轮询的客户端线程输入立即执行；其他输入原样交给原操作链，保留 ViaFabricPlus 的调度逻辑。
- 可选回归命令：`./gradlew verifyInputCompatibility -PviaFabricPlusJar="/path/to/ViaFabricPlus.jar"`。任务在 `build/input-compatibility-run` 中加载指定原始 JAR 及其内嵌依赖，不修改游戏实例，不下载或打包 ViaFabricPlus。
- 修复前该任务在 4.6.1 出现同一 `storeEvent` 注入失败；修复后 4.6.1 与 5.0.1 的实际鼠标、键盘及生命周期目标均转换通过。常规构建还验证正常输入委托、等待但未轮询时的委托、轮询时恰好执行一次、非客户端线程不直接执行。这不等于全部整合包或实际跨协议服务器测试通过。

## 皮肤预加载更新

- 首次资源加载完成时接续原版账户资料 Future，将带有纹理属性的完整 GameProfile 交给 SkinManager；下载、旧版皮肤处理和纹理注册仍由原版负责，不阻塞主线程，也不重复查询账户资料。
- 保留当前账户的皮肤 Future，供没有 PlayerInfo 的合成占位玩家读取；在主菜单停留超过原版上层缓存的 15 秒后，仍可直接使用已完成的结果。未完成、失败或离线无资料时沿用原版默认皮肤，完成后自动切换。
- 合成占位玩家在首帧之前同步本地皮肤外层开关和左/右主手，加载期间设置变更也会同步。多人切服保留的旧玩家、其他玩家继续使用原版皮肤路径；1.0.5 增加真实本地玩家等待 PlayerInfo/纹理时的临时缓存衔接，已就绪的服务器皮肤和显示状态仍优先。
- 首次多人连接现在从加密阶段（离线服从加入阶段）使用合成占位世界。首次无缓存且立即进图、网络慢或皮肤服务不可用时，不保证首帧已取得真实皮肤，也不会为了皮肤延迟进入世界。

## 1.0.2 本地交互更新

- 去掉物品栏上的额外提示，改用原版容器布局与人物预览，可本地取放、拆分、Shift 整理、拖拽分配、数字键/F 交换物品。无配方书/合成结果计算、创造物品列表或丢弃操作。
- 旧实现把「界面占用输入」当作「禁止整个移动模拟」，导致速度清零和空中悬停。现在打开 E/聊天只停止移动输入，重力、惯性、碰撞与视觉更新继续；聊天中的 W/空格不会误触移动或飞行。
- 占位阶段左键瞬间破坏已有区块内的方块（无掉落、不消耗耐久），右键仅对方块物品调用原版放置逻辑，不触发容器打开、食物、桶或投射物等使用行为。放置保留朝向、支撑与碰撞校验，成功消耗一件，包括旧服创造模式玩家。
- 数字键与滚轮选择本地快捷栏，F 交换副手；单独更新手持物品渲染器，避免换格后画面仍显示旧物品。
- 操作只修改一次性客户端世界/玩家；配置连接继续独立驱动。正常登录或失败退出时丢弃这些改动，并清除按住的攻击/使用键，防止操作延续到新服务器。
- 尚未完成 GPU 渲染及整合包实机复测；方块交互要求已有已加载的目标方块，不会凭空向单人合成虚空添加平台或物品。

## 1.0.1 问题核实（历史）

- **单人：日志确认属实。** `log/latest.log:534`、`:619`、`:704` 三次记录同一个异常：`updatePose → updateSwimming → isSpectator → getPlayerInfo` 访问到空的 `Minecraft.getConnection()`，占位构建失败并回退。后面仍成功进图，因此这是占位功能失败，不是整局游戏崩溃。
- **多人视角/手臂：源码确认存在对应缺陷，实机症状尚未独立复现。** 旧实现把全局 partial tick 固定为 `1`，包括相机眼高、FOV、手臂缓动；它们虽然每 tick 更新，却没有帧间插值，表现可能为正常 FPS 下的 20 Hz 阶梯变化。
- **多人第三人称：源码确认遗漏。** 旧局部移动没有更新步行动画、头身朝向、模型动画年龄与已开始的挥手进度，因而会沿用切服前的动画状态。
- **多人 E：源码确认被禁用。** 旧白名单只处理 F5/T/指令框，E 被当作游戏操作丢弃。

1.0.1 将初始化与局部更新放在完整的占位绑定作用域中；拆分冻结世界与实时本地视觉时钟；推进本地视觉动画。最初的 E 界面限制已由上面的 1.0.2 本地交互替代。没有多人日志，不能据此宣称已排除 Sodium、其他 Mod、真实代理切服时序或 GPU 渲染方面的问题。

- `PickBlockVerification`：使用实际原版克隆、NBT/组件序列化和物品栏操作，检查玩家头颅/墙上头颅的签名纹理资料、自定义名称/声音/额外 NBT、不同头颅不误匹配、重复选取不复制、主背包换入、满背包替换、缺失数据拒绝和实际按键射线；不启动服务器或查询皮肤服务。
- 模式回归检查 KickWarn 中冒险/旁观转生存、原有生存/创造与飞行保留、旧旁观隐身消除且隐身药水保留；控制器与本地玩家模式一致，不污染其他玩家/共享 PlayerInfo，普通加载/保存不转换。
- `LoadingTransitionsVerification`：验证资源准备到启动世界保留同一场景/玩家/视角、只跳过空会话清理、无网格时仅放行占位本地人物、HUD 仅提交进度条、原始多色换行消息、被踢首 tick 进入离线占位、650 tick 不退出、Esc 主动离开、普通踢出与异常清理。GPU 绑定使用测试夹具，不能代替实机画面验证。

- `verifyOptimizationCompatibility` 接受 JAR/目录列表，按检测到的 Mod ID 检查 Sodium/Iris/ImmediatelyFast/Lithium/FerriteCore/EntityCulling/MoreCulling/Dynamic FPS/Sodium Extra/RRLS 与 NoLoadingScreen 的共享目标；支持的 Sodium 还会检查四个私有 Mixin 和非阻塞 collector 桥。
- `EarlyLoadingVerification`：实际解码原版客户端动态注册表，并验证私有静态标签已绑定而全局标签未被修改；验证加密/离线触发、隐藏/挂载/提示界面中的初始连接单一驱动、取消连接 Future、登录成功不关闭连接、资源等待保持原版完成谓词与异常、独立保存时钟、局部输入派发。
- 保存回归额外验证实际 Gui Mixin 撤下保存界面、只在完整占位绑定内放行本地 GUI、正常/异常退出都释放场景与时钟。Mixin 转换错误会直接失败，不打开阻塞构建的崩溃对话框。

这些是源码核实和无窗口回归，不是已完成真实多人切服/渲染验证的声明。

测试代码不会被打包进 `build/libs/NoLoadingScreen-1.1.0-Fabric-26.2.jar`。测试使用的模拟连接不能代替真实代理服务器、资源包及其他 Mod 的兼容性测试。

## 实机回归清单

安装测试时移除旧 jar，改用 `NoLoadingScreen-1.1.0-Fabric-26.2.jar`，不要同时保留两个副本。以下场景应在自己有权限的测试服务器上进行。

1. **成功切服**：进入子服后切换到另一子服，等待时可以转动视角；新世界到达后使用服务器提供的位置，不保留占位移动结果。
2. **切服失败 / KickWarn**：使用 ViaFabricPlus 选择主服支持、目标子服不支持的版本，或让配置阶段拒绝加入。收到断线事件后应立即保留可操作占位，聊天栏显示红色「无法连接到服务器: 」和原始原因，不等 30 秒、不弹出断线页。等待超过一分钟仍留在占位。服务器只是不响应时，仍等待原版网络超时，不伪造被踢消息。
3. **菜单与失败同时发生**：等待时打开 Esc/E/聊天/资源包提示，再触发服务器断线；应撤下失效界面，回到可操作离线占位并在聊天中打印原因。多人正常游玩时直接被踢/封禁、连接中断也应如此；测试原因含多行、`§` 颜色和富文本颜色的情况。
4. **主动退出**：等待开始后立刻按 Esc，应出现「回到游戏」与「断开连接」，无需等待 30 秒。「回到游戏」及再次按 Esc 应恢复占位视图；「断开连接」应结束等待。
5. **退出后无残留**：断开后回到标题界面，再打开多人游戏列表；背景不应出现旧世界或占位世界。重新加入服务器也不应带入上一次的加载状态。
6. **跑跳连续性**：分别在起跳、最高点和下落时触发切服，持续按住 W+空格（含疾跑）。占位接管不应清空按键或速度，空中不套用地面阻力，落地后继续跳；其他玩家仍冻结。松 W 后减速，双击 W/疾跑键可重新疾跑；将双击疾跑窗口设为 0 时仅疾跑键有效。
7. **飞行与穿墙**：分别从地面和飞行状态切服，占位阶段继承原来的能力飞行状态；新建合成玩家从步行开始。长按空格只在落地后继续跳，不会自动飞行；松开后重新双击空格才飞行，飞行时空格上升、Shift 下降且可穿墙，再双击退出。测试墙壁、台阶、潜行边缘；退出飞行后恢复碰撞。
8. **关闭移动**：关闭「允许加载时移动」，等待时应无法平移，仍可观察世界。
9. **其他界面**：切服期间出现服务器资源包确认界面等界面时，连接不应停止推进。
10. **第三人称与聊天**：等待时反复 F5 切换三个视角，T 与 `/` 可打开输入框；输入中文/普通文字、历史记录、Tab、调整窗口大小均不应崩溃或请求补全。发送聊天显示红色「当前状态无法发言!」，执行命令显示红色「当前状态无法执行指令!」。点击聊天中的执行指令链接也应拦截。进入真实世界后不补发，正常聊天恢复。
11. **天空与群系**：白天、夜间、雨天及不同群系切服，旧世界环境保持原来的值，而不是一律改成蓝天/正午；检查单人占位世界第一帧不再黑天留太阳。下界、末地维持各自正常天空，不强制改成主世界。
12. **手部与姿势**：切服前潜行、空中飞行、游泳，等待期间松开 Shift、飞行升降、转动视角，再 F5 切换。空中飞行不再沿用潜行/游泳手部状态；水中仍保留原版水中姿势逻辑。对比眼高和手臂旋转是否逐渐收敛，不能卡在旧偏移。
13. **普通流程**：检查单人开图、正常多人加入及切换维度；禁用 Mod 后仍走原版加载流程。
14. **单人回归**：连续进入三个不同存档，占位阶段应显示虚空/天空；日志不应再有 `Could not build/install the placeholder world` 或 `Placeholder world failed`。若加载太快无法观察，不算已验证视觉效果。
15. **帧间流畅度**：在较长的切服间隙，分别飞行、疾跑、潜行/站起并转动视角，确认 FOV、眼高和手部不是每 50 ms 跳一格。F5 下边走边转头、停步，四肢应继续摆动并逐步停下，其他玩家仍冻结。
16. **物品栏**：等待时按 E，应看到人物预览，且没有多余提示；测试左右键取放/拆分、Shift 整理、拖拽分配、数字键/F 交换物品，并核对快捷栏/手上物品。E/Esc 关闭，重新打开保留本地改动；保持界面到进服、被踢或失败时应自动关闭，真实背包以新服数据为准。
17. **界面不冻结运动**：起跳、下落、疾跑中分别打开 E 和聊天，应继续惯性/重力/碰撞，不能悬空。动画逐渐回到静止，聊天输入 W、空格等不触发移动/双击飞行。飞行时开界面保持飞行能力，但停止推力。
18. **本地方块操作**：分别在保存、切服等待和 KickWarn 中长按左键并转动视角，一次按下最多破坏一个方块（含高硬度方块），无掉落；松开重新点击才破坏下一个。右键放置方块，朝向、台阶/楼梯、水中替换和门/床等多方块结构应合理，扣减数量，碰撞/位置不合法不扣减；按住右键按原版间隔连续放置。分别测试主副手、数字键与滚轮；箱子右键不打开，非方块物品不执行使用动作。测试 Sodium 开关下网格更新。
19. **交互切服隔离**：保留本地放置/破坏/背包交换结果并按住左右键直到登录完成；新世界不得保留这些改动或继续攻击/放置，重新按键后才恢复真实交互。其他玩家/真实服务器世界不受影响。
20. **皮肤与主手首帧**：使用自定义皮肤启动游戏，在主菜单停留至少 20 秒后进入较慢的单人存档，观察第一人称袖子、F5 和 E 人物预览；应直接使用已加载的真实皮肤，外层与设置一致。分别检查细/宽手臂及左/右主手，连进两个存档检查缓存复用；加载期间切换外层/主手设置后应更新。
21. **皮肤尚未就绪**：首次无缓存快速进图、网络慢或离线启动时，不应因皮肤请求卡住进图或崩溃；尚未完成时允许默认皮肤，若请求随后成功则应在占位阶段自动显示真实皮肤。不能将这种未就绪场景算作首帧保证。
22. **多人皮肤隔离**：有服务器换肤功能时先应用与账户不同的皮肤再切服，等待期间应保留旧服皮肤、外层和主手，进入目标服后已就绪的目标服数据必须优先。真实本地玩家缺少 PlayerInfo/纹理时可临时使用账户预加载皮肤，其他玩家不受影响；目标服返回默认皮肤或空结果后不能永久沿用缓存。

23. **保存退出**：使用备份存档，分别从暂停菜单和正常活动状态保存退出，在较长保存期间测试鼠标、F5 三视角、E/Esc 开关、WASD、双空格飞行、升降及数字键/滚轮。保存结束自动回主菜单；重新打开存档，保存期间的本地方块/背包/移动改动不得出现。移动配置关闭时仍能转头但不能平移。
24. **准备资源**：打开已有世界，在「准备资源中」就能观察占位世界并操作；转动镜头、切 F5 及打开 E 后继续等到启动世界，应保留同一视角/菜单、不闪菜单或泥土背景，第三人称能看见人物；中央区块状态矩形应消失，只保留上方文字/进度条。分别测试数据包错误、安全模式重试、备份提示、低磁盘空间提示及 bundled resource pack。提示不得消失，取消不得留下占位世界，失败不得占用存档锁。
25. **首次多人连接**：在自有在线模式测试服延长加密/配置等待，确认从加密开始进入占位；检查离线服加入回退、认证失败、配置断线、资源包接受/拒绝/重载、Esc 取消后立刻重连。操作占位玩家不得产生发往真实连接的移动、飞行、背包或方块操作包，登录位置和能力以服务器为准。
26. **等待期边界**：保存期间失焦/重新聚焦、调整窗口及关闭窗口，保存仍须完成。F3 组合调试动作与好友加入入口在占位阶段不执行，防止同步等待中嵌套重载/加入；截图与 F5 不受此限制。首次预热尚未完成时允许原版等待界面，不阻塞认证。
27. **ViaFabricPlus 共存**：保留 ViaFabricPlus 4.6.1 启动，确认没有 `storeEvent` 注入错误；测试正常游戏的键鼠、菜单点击/滚轮/文字输入和单人保存中的局部输入。分别检查默认协议及有权限的旧协议测试服，正常游戏时 ViaFabricPlus 的输入同步行为不应被绕过；不能只凭标题界面可打开就认定跨协议玩法或反作弊兼容。

28. **永久占位退出**：KickWarn 中测试移动/飞行、长按破坏限制、放置与背包、聊天拦截；按 Esc →「断开连接」后应立即回到原父界面，重新进服时不恢复旧方块/背包改动，不再出现旧踢出消息。Mod 关闭时被踢应恢复原版断线界面；单人保存完成仍自动离开，不能被 KickWarn 留住。

29. **离线模式**：分别以生存/创造/冒险/旁观被踢，前两者保持原模式，后两者变为生存；查看 HUD 和 F5 人物、测试破坏/放置与飞行。原旁观模式不应只剩透明头部，真正的隐身药水效果应保留。成功切服、单人保存以及其他玩家的模式不受影响。
30. **中键与头颅数据**：在占位/KickWarn 中分别中键普通方块、两种不同皮肤的玩家头颅及墙上头颅，无需 Ctrl；检查手持模型、名称及 NBT/数据组件，不能退回史蒂夫头。重复选取同一物品应选择已有栈；测试背包中的匹配物品换入、满背包替换、修改键位和主动退出后不带入真实世界。客户端未收到的容器内容无法复制，方块实体未就绪时应不选取。
31. **离线快捷栏物品名**：被踢进入永久占位后，用数字键和滚轮在不同名称物品、同物品同名称及空格之间切换。名称应按「通知显示时间」选项出现并淡出，不得永久固定；设为 0 时不显示，打开会暂停 HUD 的菜单时遵循原版暂停语义，关闭后继续。与 ImmediatelyFast/Iris 同时安装时重复此项。

占位移动用于加载/保存间隙和 KickWarn 离线场景，真实服务器发来的位置和能力始终优先；不会把占位坐标、速度或飞行权限迁移到新服务器。合成的单人虚空提供虚拟落脚面；水流、梯子、载具等完整游戏物理不属于该局部模型。加载期背包是本地操作界面，不提供创造模式物品列表/配方书/合成/丢弃，也不会把本地修改带入新世界。

记录问题时保留 `logs/latest.log`，注明是否安装 Sodium 或其他改变加载与渲染的 Mod，以及失败发生时是否开着菜单。
