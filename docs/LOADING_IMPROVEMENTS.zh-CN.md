# 加载与保存交互改进

## 本次增量：优化 Mod 目标转换兼容与离线快捷栏文字

当前项目仍是 Fabric 客户端 Mod。本次没有把 Forge/NeoForge 的 Mod 当作 Fabric JAR 直接适配；先针对 26.2 Fabric 生态补齐实际版本检查。对 Lithium、FerriteCore、ImmediatelyFast、EntityCulling、MoreCulling、Dynamic FPS、Sodium Extra、Reese's Sodium Options、Iris、RRLS，以及更重的 Bobby、Distant Horizons、FastQuit，现有生产代码不调用它们的私有 API，而是依靠可串联的原版生命周期包装。新增 `verifyOptimizationCompatibility`，通过调用者提供的未修改 JAR/目录运行 Mixin 目标转换检查；它会报告 NoLoadingScreen 钩子是否在这些 Mod 加载后保留，不把类转换成功误报为 GPU、FPS 或真实玩法兼容。

Sodium 的私有区块优化仍单独按精确版本门控，目前只对 Minecraft 26.2 最新正式版 `0.9.2+mc26.2` 启用；未知或预发布版本自动跳过私有钩子，不因版本号相近而冒险套用内部字段/方法。当前额外验证的 26.2 版本包括：Sodium 0.9.2、Iris 1.11.4、ImmediatelyFast 1.16.4、Lithium 0.25.3、FerriteCore 9.0.0、EntityCulling 1.10.5、MoreCulling 1.8.1、Dynamic FPS 3.11.9、Sodium Extra 0.9.3、RRLS 5.2.8、ViaFabricPlus 5.0.1、Bobby 5.2.15、Distant Horizons 3.2.0-b、FastQuit 3.1.5 和 Reese's Sodium Options 2.2.3。Nvidium 当前 26.2 构建要求 Sodium 0.9.1，与已验证的 Sodium 0.9.2 不满足依赖，因此不列入已认证组合。

离线占位世界在渲染时绑定临时玩家，但 `Gui.tick` 过去没有为其中的 `Hud.tick(boolean)` 绑定，导致原版 `toolHighlightTimer` 不递减，切换快捷栏后名称可能永久停留。现在只包装这一处已有调用，保持原版调用次数、暂停参数、物品/名称比较和通知时长；不绑定整个 `Gui.tick`，死亡/睡眠/界面生命周期仍按原版看到空世界。无窗口回归覆盖不同物品切换、倒计时、暂停以及空物品栏清除，并验证占位字段每次调用后还原。

## 1.0.5 增量：首次进图冷启动

用户复测确认皮肤回退已不再出现，本轮不改皮肤逻辑，继续处理首次单人/多人进图卡顿。

### 新证据

- 实际客户端 19:11 的日志显示，首次单人登录装配耗时 367 ms，普通客户端任务耗时 254 ms；稍后多人收包出现 782 ms 的单次调用。这些操作位于软预算内部，不能通过缩小每帧预算抢占。`login world assembly` 与外层 `client packet drain` 可能是同一段时间，不能相加。
- 独立 GPU 测试使用本机 RX 580、原版资源、Fabric API 与 Sodium，不打开存档、不建立游戏服务器连接。JFR 在首次占位安装时采到多次 JAR 读取、类加载与 Mixin 转换，分别位于监听器、ClientLevel、玩家、区块调色板及 Sodium 渲染缓存初始化中，说明冷加载也是实际开销，不只是区块建模。
- 这不是用户完整整合包的 FPS 采样，不能据此把全部 782 ms 归因于某个类或 Sodium。用户日志还存在其他协议解码错误，本轮不宣称已经修复这些独立兼容问题。

### 改动

1. `JoinClassWarmup` 在首次资源加载完成、显示初始菜单/Quick Play 之前，解析已确认的进图相关类型及一层嵌套类型的签名。使用 `Class.forName(..., false, ...)`，不调用类初始化器或构造器，不构造世界/网络对象。此处仍在启动线程执行，避免专门开后台线程并发触发 Mixin 类转换；这是把一次性开销前移，不是宣称所有世界逻辑都异步。
2. 同一启动收尾阶段，Sodium 地形的 SOLID、CUTOUT、TRANSLUCENT 三个实际 RenderPipeline 由 GPU 预编译，后续复用原缓存对象，不复制 GLSL/宏定义。不启动真实世界；临时渲染器在 finally 释放。GPU 调用保持在渲染线程，失败只记录警告，仍保留原版首次使用路径。后续资源包使 GPU 缓存失效时仍按正常流程重编译。
3. Sodium 在 `loadLevel` 已创建渲染器，原版首帧又触发几何失效。仅当渲染器还未使用、有效视距相同、期间没有资源重载时，合并这一次重复 `reload`。第一次使用、本地方块重建请求、卸载均清除标记；资源代次或视距变化仍重建。
4. 合成空世界只创建一个 Sodium 区块工作线程，不再为没有地形任务的场景创建整组线程及其上下文。真实/接管世界保留 Sodium 配置的线程数，用户设置不变。所有 Sodium 私有钩子和预热仅限制到当前已验证的正式版 `0.9.2+mc26.2`。
5. 慢日志细化到 `packet <具体包类>`、`Sodium renderer initialization`、`Sodium renderer teardown`；直接从资源等待循环调用的渲染帧也纳入计时。只记录类型和耗时，不记录包正文。
6. 补齐 Fabric 的配置阶段槽位保护：实际 `setClientPlayAddon` 在配置 addon 存在时也会拒绝。此前只检查 play 槽位不够，现在任一槽位占用都拒绝合成，不清空真实网络所有者。

### 验证与限制

- 常规回归及实际 Sodium/Fabric API/ViaFabricPlus 4.6.2 转换检查通过；本次另用 Sodium 0.9.2 + Fabric API 0.158.0 + ViaFabricPlus 5.0.1 完成加载策略回归。新增 16 项 Sodium 冷启动断言，覆盖实际管线对象复用、首次重建合并及失效条件、工作线程隔离；另验证类型预热不执行类初始化器/构造器，以及 Fabric 配置槽位不被改动。
- 新增可选 `verifyColdStartGpu`，在 `build/cold-gpu-run` 启动图形客户端，显示合成占位 3 秒、验证未泄漏世界绑定/交换链图像后正常退出。具有两分钟任务超时及成功标记检查，测试类不进入分发包。初版测试驱动曾在 preLaunch 后台加载类导致测试 JVM 死锁，已改为测试专用主线程帧尾钩子，随后真实 OpenGL 测试通过。
- 开发中间态（已做线程/着色器优化，未做类预热）首次占位安装约 311 至 338 ms；加入类型预热后的两次独立客户端测试约 195、197 ms，启动类型准备分别约 206、232 ms，着色器预编译约 17 ms。**不是前后正式版的完整基准，也不是零卡顿保证**：首个场景仍有约 200 ms 开销，整合包、真实区块与服务器场景还需复测。前移准备会增加客户端启动收尾时间。
- 保持版本 1.0.5，不修改语言文件、皮肤修复或用户游戏目录中的 JAR。完整测试命令见 [测试说明](TESTING.zh-CN.md)。

## 1.0.5 增量：皮肤交接与加载主线程开销

### 已核实的问题

- 合成玩家能读取账户预加载皮肤，但真实 LocalPlayer 出现后原来立即恢复原版查询。此时 PlayerInfo 尚未到达，或它的皮肤 Future 尚未完成，就会短暂回退到按 UUID 选择的默认皮肤。新版默认皮肤不止 Steve/Alex；外观看似随机不等于账户皮肤被修改。
- 26.2 `Minecraft.runTick` 在输入/渲染前将 `PacketProcessor` 队列处理到空，又将普通客户端任务处理到空。区块数据的主线程应用不等于异步网格建模，批量接收足以推迟整帧渲染。
- 原版 `LevelRenderer.compileSections` 有同步建模分支；实际安装的 Sodium 0.9.2 在 `updateChunks` 中会等待 `ChunkJobCollector`，并可把未开始的任务拿到渲染线程执行。仅开启后台构建器不代表主线程不会等待。
- 用户客户端 `2026-09-13-1.log.gz` 记录单人首次进图 2989 ms，后续为 1336、890、857、623、617、596 ms 等。`latest.log` 有多人接收阶段 1142 ms，以及进入前后反复启动/停止 Sodium 的 10 个工作线程。这些记录支持冷启动及客户端开销存在，**不是掉帧曲线，也不能单独证明 Sodium 是唯一原因**。
- 同一 `latest.log` 还确认：ViaFabricPlus 4.6.2 的 `enableAutoRead` 收尾仍需要原连接 channel，本 Mod 的 RETURN 注入却已替换成空连接，导致切服异常和超时；另一次合成监听器构造撞上已占用的 Fabric play addon。

### 实现

1. 真实本地玩家先执行原版皮肤查询；仅在返回默认皮肤且 PlayerInfo 未到达/纹理仍在加载时使用已完成的账户皮肤。服务端皮肤、披风、模型等一旦就绪即接管；完成的空结果/默认皮肤也优先，不永久覆盖服务端换肤。其他玩家、接管的旧玩家和禁用 Mod 时不受影响。不阻塞下载，不保证无缓存离线/快速进图首帧已有自定义皮肤。只在 `SkinManager.createLookup` 内观察原版实际取得的 Future，绝不为了查询就绪状态再次访问可能过期的缓存。
2. 仅客户端自己的收包队列在加载期间使用每帧 **8 ms 软预算**；普通客户端任务使用 **4 ms 软预算**。在完整处理一个包/任务后让出，至少处理一个，不移动/删除/重排队列元素。剩余项在后续正常帧处理，继续使用原线程及异常处理。集成服务器的队列不受影响；保存/资源等待的 `managedBlock` 保持原版完成语义。
3. 原版加载期间的同步区块建模请求转给已有 `compileAsync`。Sodium 可选钩子在加载期间不调用 `awaitCompletion`，结果仍由工作线程发布到其原有结果队列。显式 `updateImmediately`（Flawless Frames）保留完整完成要求；没有安装 Sodium 时没有必需依赖，未来 Sodium 版本或其他构建未经验证时，版本检查会停用这两个私有布局兼容钩子，保留其原生调度；当前仅启用精确正式版 `0.9.2+mc26.2`。跳过等待的未完成 collector 会暂存，完成后释放；随后切到完整帧或恢复普通玩法时仍会等待这些旧批次，不能只等待新任务。
4. 加载保护覆盖占位、等待世界、接收区块，以及原版提前就绪后的 **5 秒**，防止首个区块到了就取消保护。之后恢复普通玩法策略，断开和禁用也会退出；不把这 5 秒当作区块全部加载完成的判据。合成虚空的有效渲染距离限制到最多 2，减少无用 section 图和缓冲分配，不修改保存的设置，也不缩减真实/接管世界。
5. 切服接管改为包装完整 `handleConfigurationStart`，在其他 RETURN 钩子结束后才替换旧监听器连接。Fabric 槽位已被占用时直接拒绝合成，不清空他人的槽位，不再等构造抛异常。
6. 加载中对超过 100 ms 的收包、普通任务、客户端 tick、渲染帧及登录装配写入 `[loading-work]` 日志，并限制报告数量。它记录整个调用链的墙钟时间，可能包含其他 Mod、GC/JIT、驱动及垂直同步等待，不代表该 Mod 的独占 CPU 耗时。原来的 `setLevel` 日志不再错误地把此前全部时间写成等待服务端。

**行为边界：** 这次确实改变了接收包/任务处理时机，不能再宣称“不延迟任何网络数据包”。不创建、丢弃或重排协议包，响应仍由原版处理器产生，但分帧会使一些处理及相应回复晚于原来的整批清空。8/4 ms 不是硬实时保证：单个处理器、注册表应用、渲染器销毁、资源上传、着色器编译和驱动等待仍可能超出预算。不能把读写共享 ClientLevel、注册表及 GPU 的所有代码直接搬到任意线程。本轮没有重写这些线程安全契约，也不承诺总加载时间更短或彻底消除每次卡顿。

### 验证

- 常规 `check` 执行真实变换后的收包/任务队列，验证 FIFO、跨帧进度、原版错误处理、处理过程中开始登录、集成服务器隔离、异常清理、嵌套同步等待、保护期结束、异步建模路由和合成距离隔离；实体回归覆盖无 PlayerInfo、纹理未就绪、服务端换肤、空结果、其他实例与禁用。
- `verifyLoadingCompatibility` 使用提供的原始 Sodium、Fabric API 和 ViaFabricPlus JAR，验证目标转换、等待条件、完整帧模式跨帧补等、真实 collector 完成状态、连接收尾包装及 Fabric 槽位保护；当前已跑过 Sodium 0.9.2 + Fabric API 0.158.0 + ViaFabricPlus 5.0.1，也保留此前 ViaFabricPlus 4.6.2 的记录；不下载或打包这些 Mod。
- 这些是无窗口回归，**未完成该整合包的真实 GPU/FPS 和进服复测**。尤其需要复测高渲染距离、资源包重载、快速取消/切服、弱 CPU/GPU，以及首次与第二次进图。具体步骤见 [测试说明](TESTING.zh-CN.md)。版本仍为 1.0.5，未改语言文件。

回归新增带签名纹理资料的普通/墙上玩家头颅、NBT 与组件往返、快捷栏/背包匹配、满背包、缺失数据与按键路由测试；另验证四种模式、缓存资料隔离、旁观隐身与药水效果，以及正常加载模式不变。实机仍需复测本轮新增行为。

- **结构复用**：保存、切服、被踢共用 `OutgoingWorld` 场景快照和 `PlaceholderWorld.adopt`；隐藏的配置界面直接调用原版 `ServerReconfigScreen.tick()`，不再复制连接更新分支。删除未使用的占位/HUD 查询函数。
- **破坏按键**：只消费原版 `keyAttack.consumeClick()`，不把 `isDown()` 当成重复攻击。保存、切服和永久离线占位均为一次按下最多破坏一个方块；右键仍沿用四 tick 连续放置间隔。
- **资源准备到启动世界**：仅跳过 `doWorldLoad` 中重复的空会话清理（无真实世界、玩家、本地服务器及待连接对象时）。复用已有占位世界与玩家，不切换注册表、不重建相机；从原版新建的 `LevelLoadingScreen` 直接获取 tracker，再隐藏界面。真实连接/错误/确认界面的清理仍保留。
- **第三人称人物**：合成虚空没有已编译区块网格，原版 `LevelExtractor.isEntityVisible` 因此剔除了玩家。现在只对完整绑定的占位本地玩家放行网格可见性检查；仍复用原版实体列表、视锥、第一/第三人称判定、皮肤与人物渲染器，不伪造区块或另画一份人物。

- 离线占位**没有停留超时**，保留飞行、破坏、放置、快捷栏、E/F5 等本地机制。按 Esc →「断开连接」主动离开；普通主动退出、成功协议转服、单人保存/错误不触发 KickWarn。
- 聊天栏通过原版 `addClientSystemMessage` 打印红色前缀 `无法连接到服务器: `，后面直接附加服务器原始 `Component`。中性的父组件实现 `§c前缀§r` 的效果，不把原文本转换为纯字符串；原有富文本颜色、`§` 格式、显式换行及聊天宽度自动折行均保留，聊天历史使用原版 `storeState/restoreState` 保存恢复。

`LoadingTransitionsVerification` 覆盖实际 Mixin 钩子的上述生命周期、650 tick 永久停留和多色换行消息；ViaFabricPlus 4.6.1 原始 JAR 的相关目标类转换也通过。**这些不是 GPU/真实服务器验收**；仍须测试实际跨版本子服拒绝、资源包重载和整合包第三人称显示。KickWarn 只保留客户端场景，不维持服务器连接，不绕过踢出/封禁，也不伪造尚未收到的错误原因。

## 1.0.3 实现

### 飞行中切服

旧实现的 `PlaceholderWorld.resetMovement` 和 `PlaceholderControls.reset` 会把飞行开关设为 false，给正在飞行的旧玩家重新施加重力。现在继承旧玩家的**能力飞行状态**、速度及持续按键；新建的合成玩家仍从步行开始，双击空格仍可切换飞行。聊天或关闭移动配置不会把继承的飞行取消。

这里只保留占位视图的状态，不把旧服飞行权限写给新服；新世界仍以服务器的能力包为准。鞘翅滑翔、水流及载具物理不是该局部移动模型的完整复刻。

### 等待区块时镜头像被卡住

源码发现位置锁定只保存最初坐标，后续服务器传送不会更新它。客户端可能被拉回旧锚点，引发服务器反复校正坐标/视角。另外旧实现写入 `onGround=true`，可能触发原版落地取消飞行。

现在在 `ClientPacketListener.handleMovePlayer` 原版方法返回后，使用**原版已经解析好的绝对/相对传送结果**更新锚点；确认包仍由原版按原顺序发送。等待仅修正位置和本地坠落速度，不改 yaw/pitch，也不伪造落地。位置锁定绑定到当前玩家，拆除世界时清理。

无窗口回归验证了实际鼠标路由、相机朝向、绝对/相对传送处理和原版确认包顺序。**尚未独立复现用户整合包中的特定卡镜头场景**，因此不能据此排除鼠标焦点、其他 Mod 或 GPU 问题；仍需实服复测。

### 单人保存退出：保留画面，也保留本地操作

`Minecraft.disconnect` 的同步循环只调用 `renderFrame(false)`，既不轮询输入，也不推进本地移动。旧版只是保留画面，所以仍像定格。

`SavingWorldView` 继续在拆除前捕获旧场景，断开旧监听器后接管；`LoadingWaitLoop` 在原保存循环内轮询 GLFW 输入，用独立 20 Hz 时钟推进占位移动/动画，逐帧处理鼠标。F5、E、WASD、双空格飞行、快捷栏和原有本地交互共用占位实现。E/聊天停止输入但不暂停运动。保存时不运行 `Minecraft.tick`、真实玩家 tick、连接 tick 或通用任务队列。

`GuiMixin` 仅在完整的断线占位绑定内允许关闭保存提示，不修改全局 teardown 标记。保存文字移到 HUD；Esc 打开仅能返回的菜单，不提供中断保存。原 `server.isShutdown()` 条件和退出顺序保留，正常/异常退出都释放场景和本地时钟；占位失败恢复原版保存界面。

**边界：保留的是静止的旧世界，不是区块逐个消失的动画。** 原版服务器的保存/卸载过程不向已断开的客户端报告进度，客户端最后统一释放网格。要让区块按某种顺序消失，需要另做视觉动画（不能冒充实际保存进度），或改造客户端网格释放调度；后者兼容 Sodium 等渲染器的工作量明显更高。本轮没有实现这些额外行为。

## 单人「准备资源中」提前占位

在 `WorldOpenFlows.openWorldLoadLevelStem` 显示 `selectWorld.resource_load` 后触发。`loadWorldDataBlocking` 仍使用原版 `managedBlock`，只包装完成谓词插入本地帧，不改变资源加载 Future、完成执行器或异常路径；处理完成任务前占位字段已解绑。数据包失败、安全模式重试、备份与低磁盘空间提示保留原版逻辑，不吞掉确认界面。

## 多人「通讯加密中」提前占位

`ConnectScreen.updateStatus` 收到 `connect.encrypting` 时仅发布 volatile 标记，下一次客户端 `ConnectScreen.tick` 才安装世界。跳过加密的离线服在 `connect.joining` 触发。认证、密钥、压缩、配置数据和握手包全部保留原版实现。

隐藏原连接界面后仍保留其 tick 所有权；若原界面挂载则交给原版，避免重复 tick。资源包提示或加载菜单不会停止连接；Esc 可立即取消，并按原版锁顺序设置 aborted、取消 channelFuture、关闭连接、返回原父界面。成功登录仅释放所有权，不关闭连接；失败回退可重新挂载同一个界面，不把它误判为新连接。

## 提前注册表与安全边界

`PlaceholderRegistries` 在游戏首轮资源加载完成后异步预热，使用游戏自带 vanilla server-data pack 和 `RegistryDataLoader.SYNCHRONIZED_REGISTRIES` 解码客户端数据。静态注册表的 holder 也独立复制，只向副本绑定本地标签，避免首次加载缺少标签或污染真实服务器标签。没有强转 `VanillaRegistries.createLookup()`，也不读取当前存档/服务器的数据包。无窗口测试实际执行这条解码路径。

预热未完成时保留原版界面，后续 tick/等待帧重试；构造/安装失败则回退，不阻塞网络等待。合成 play 监听器仍用 `PlayAddonGuard` 保护 Fabric networking 槽位，真实 play 监听器已经存在时不再构造占位监听器。

占位连接没有 channel；占位玩家不执行真实 gameplay tick。坐标、飞行、背包、方块改动仅留在一次性客户端对象，交接时丢弃，攻击/使用与排队点击不重放。F3 组合调试动作、好友加入入口在占位期间不执行，以免在同步等待中嵌套重载/加入或访问拆除中的真实字段。不能据此保证所有服务器或额外 Mod 的反作弊/兼容性策略；仍须自有服务器实测。

### 后续验收范围

首次启动且无缓存、快速登录、延迟加密/认证/配置、离线/LAN；DNS 与通道连接失败；每个阶段取消后立即重连；原始踢出原因；资源包接受/拒绝/重载、行为准则与对话框；Fabric networking/Sodium 共存；占位构造/渲染失败回退。全部路径须保证真实连接恰好由一个所有者驱动，占位操作不向真实 socket 发包，真实世界及注册表到达时完整替换本地默认值。

## 验证说明

`./gradlew build` 会运行移动模型与无窗口 Fabric Mixin 回归。它们不等价于实机测试，保存场景的 GPU 绑定、真实存档保存以及多人代理时序还需按 [测试清单](TESTING.zh-CN.md) 检查。构建产物：`build/libs/noloadingscreen-1.0.5.jar`。
